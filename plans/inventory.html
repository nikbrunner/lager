Popup behavior

A menu over the table

The action menu opens as a bordered popup. The current row, query and marks stay visible behind it. Every application action is available here. Repository actions, Copy, Selection and Remote open submenus in the same popup.

Arrow keys or the configured movement keys select a menu item. Enter activates it. Esc returns one level; at the root menu it returns to the table. Destructive confirmation starts focused on Cancel.

At 80 × 24, long popups scroll internally. The title and action hints stay visible. Full paths wrap in inspection and confirmation. The main view is rows only, without a detail pane. At 80 × 24, path and origin move into on-demand inspection so the main status columns stay readable.

What Ratatui supplies

Ratatui has Clear to cover the underlying cells, Block for the frame and List for selectable items. Lager supplies the menu state, keyboard handling and action availability.

Use those built-ins for this small menu. A separate popup/menu dependency is unnecessary.

Your bindings, these defaults

All Lager-owned shortcuts are configurable per input mode. Help, menu hints and the footer show the effective bindings, not hard-coded defaults. Native Git and shell key handling, including Ctrl-C during handoff, stays under the terminal's control.

Example configuration

Proposed syntax in the selected Lager TOML config. An omitted action keeps its default; a supplied list replaces that action's bindings.

[inventory.keys.normal]
remove = ["x"]
menu = ["M"]
add = ["a"]
clone = ["c"]
row_down = ["j", "Down", "Ctrl+n"]

[inventory.keys.menu]
next = ["j", "Down", "Ctrl+n"]

[inventory.keys.search]
accept = ["Enter"]
cancel = ["Esc"]

The default direct keys are a small set: row movement, search, marking, Add, Remove, Inspect, Refresh, Menu, Help and Quit. Other actions live in the menu and can receive custom shortcuts, such as clone = ["c"]. The prototype preset demonstrates Remove → x and Menu → M.

Rules that keep remapping predictable

Bindings name actions, not characters in a giant global map. Normal mode, menus, search, reference input, confirmation and detail views have separate maps. Text fields receive ordinary text rather than normal-mode action shortcuts.

Duplicate bindings for different actions in the same mode and unknown key/action names are configuration errors. Uppercase letters are distinct. Arrow keys are default aliases, not unchangeable fallbacks.

Accept/cancel and a path to help/quit must remain reachable. Reject a config that removes those exits. Invalid refresh keeps the current valid map and shows an error; valid changes apply together after local/config refresh.

Popup modes inherit shared dialog focus/activate/cancel defaults, with per-mode overrides. Text-input command bindings cannot consume ordinary unmodified printable characters. No in-app binding editor or key sequences are required. Defaults require no config entry.
